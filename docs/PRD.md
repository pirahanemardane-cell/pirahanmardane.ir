# PRD — پیراهن مردانه (pirahanmardane.ir)

نسخه: 1.0 · تاریخ: 2026-08-30  
وضعیت: زنده روی production · محدوده این سند: الزامات محصول بدون وابستگی به فعال‌سازی نهایی درگاه/پترن SMS

## 1. خلاصه محصول
بازارگاه پوشاک مردانه با سه نقش: خریدار، فروشنده، ادمین.  
دامنه: https://pirahanmardane.ir

## 2. اهداف
- خرید امن با OTP و نقش‌بندی
- فروشنده: ثبت کالا، سفارش، تسویه، گزارش حسابداری CSV
- ادمین: نظارت فروشنده/سفارش/تیکت/خطا

## 3. نقش‌ها و دسترسی
| نقش | دسترسی اصلی |
|-----|-------------|
| buyer | کاتالوگ، سبد، سفارش، پروفایل، مرجوعی |
| seller | پنل فروشنده، کالا، سفارش، شبا، payout، CSV |
| admin | پنل ادمین، sellers، orders، tickets، audit |

## 4. الزامات کارکردی (Functional)
### 4.1 احراز هویت
- OTP ثبت‌نام / ورود / بازیابی (لایه کد آماده؛ فعال‌سازی provider جدا)
- ورود رمز (login-password) + تشخیص ورود مشکوک
- پروفایل: تغییر موبایل/رمز با اطلاع‌رسانی

### 4.2 کاتالوگ و خرید
- PLP/PDP، سبد، ثبت سفارش
- وضعیت سفارش: pending_payment → paid/processing → shipped → delivered / cancelled
- رهگیری و تأخیر ارسال

### 4.3 فروشنده
- CRUD محصول، آپلود تصویر WebP
- تأیید/رد/ارسال سفارش
- تغییر شبا، درخواست تسویه
- خروجی CSV حسابداری (ناخالص، کمیسیون، خالص)

### 4.4 ادمین
- مدیریت فروشنده (از جمله archive)
- سفارش‌ها، تیکت/اختلاف
- critical log

### 4.5 اعلان
- لایه SMS رویدادمحور (essential + recommended) با mock تا فعال‌سازی provider

## 5. الزامات غیرکارکردی
- Rate-limit روی OTP/login/orders/pay-initiate
- ایندکس DB روی جداول پرتکرار + pg_trgm
- Cache bypass برای /api و پنل‌ها (Cloudflare)
- UTF-8 CSV برای Excel
- Secrets فقط در Vercel env

## 6. Acceptance criteria (نمونه)
| ID | معیار | Pass |
|----|--------|------|
| AC-01 | خریدار بدون لاگین سبد می‌بیند؛ checkout نیاز به auth دارد | دستی |
| AC-02 | فروشنده فقط سفارش‌های خودش را می‌بیند | دستی |
| AC-03 | ادمین بدون نقش admin به /api/admin* رد می‌شود | دستی |
| AC-04 | CSV فروشنده ستون‌های gross/commission/net دارد | API |
| AC-05 | تغییر محصول کش کاتالوگ را invalidate می‌کند | کد |
| AC-06 | /api/* در CF با DYNAMIC/BYPASS است | curl |

## 7. Out of scope (این فاز)
- درگاه پرداخت واقعی پایدار (جدا)
- bodyId پترن ملی‌پیامک در env (جدا)
- صف job، read replica، موتور جستجوی اختصاصی
- اپ موبایل native

## 8. اولویت باقی‌مانده وابسته به بیرون
1. پترن SMS + SMS_MOCK=false  
2. درگاه + خاموش mock پرداخت  
3. لانچ رسمی (noindex off پس از تست)
